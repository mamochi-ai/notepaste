# AI APIなしで実現できる品質と限界の分析

実装前の検討結果です。結論から書きます。

## 結論

- **「毎回まったく新しい物語を、自然な日本語で約1,200字」は、AI APIなしでは実現できません。**
  文章を単語や文の単位でランダムに組み合わせる方式では、文法は保てても、因果・視点・時間・人物の整合性がすぐに崩れます。
- 実現できるのは **「人間が書いた物語の骨格と場面の文章を、状態（人物・場所・時間・伏線）を管理しながら組み立てる」方式** です。
  これを本プロジェクトでは「モジュール型の作家主導生成」と呼びます。
- この方式なら、**毎回表面の文章・人物・舞台・展開の分岐・結末・テンポが変わり、かつ物語として破綻しない** 短編を作れます。
  ただし「新しさ」の上限は、人間が書いた骨格の数で決まります。同じジャンルを10回ほど読むと、読者は骨格の共通性に気づきます。

Ver.0.1はこの代替設計で実装しています。

## 方式ごとの比較

| 方式 | 自然さ | 多様性 | 整合性 | 判断 |
|---|---|---|---|---|
| A. 完成済み小説をランダム選択 | ◎ | ✕（本数分だけ） | ◎ | 指示により不可 |
| B. 文・語句のランダム連結 | ✕ | ◎ | ✕ | 小説として成立しない |
| C. マルコフ連鎖などの統計生成 | ✕ | ○ | ✕ | 1,200字の一貫性を保てない |
| D. 骨格＋場面テンプレート＋状態管理（採用） | ○〜◎ | ○ | ○〜◎ | 現実的な最適解 |
| E. ブラウザ内で動く小型LLM（WebLLM等） | △〜○ | ◎ | △ | 数GBのダウンロード、iPadでは動作が厳しい。将来の選択肢 |

## 方式Dで保証できること

1. **人物の一貫性**：人物はデータ（姓・名・性別・一人称・年齢層・外見の特徴）として一度だけ決め、本文中は必ず変数で参照する。本文データに「彼」「私」などを直接書くことを自動検査で禁止する。
2. **視点の一貫性**：一人称／三人称を物語ごとに決め、主人公の呼び方を変数で切り替える。一人称なのに地の文に主人公の名前が出る、といった誤りは自動検出する。
3. **時間・季節・天候の一貫性**：舞台ごとに許される時間帯を定め、季節・天候に依存する描写には条件を付ける（雪は冬だけ、夕焼けは晴れの夕方だけ、など）。
4. **因果と伏線**：伏線となる小道具（モチーフ）は骨格の前半で提示し、後半で必ず回収する。分岐で立てたフラグに合う結末だけを選ぶ。
5. **情報の順序**：主人公がまだ名前を知らない相手を、名乗る前に名前で呼ばない（骨格に「紹介される場面」を宣言して検査する）。

## 方式Dの限界（隠さずに書きます）

1. **骨格の再読性**：同じ骨格からの物語は、細部が違っても筋は似る。試作データは1ジャンル1骨格なので、同ジャンルを続けて読むとすぐわかる。
   → 対策：骨格を増やす（1骨格あたり人間の執筆量は約4,000〜6,000字）。骨格数が品質の上限を決める。
2. **文体の幅**：「です・ます調」と「だ・である調」の自動変換、方言、語り口の大きな変化は、文末活用の機械変換が不自然になりやすいため行わない。文体の変化は「人称」と「テンポ（文の長短・描写密度・段落の長さ・展開の数）」に限定する。
3. **歩数による変化の範囲**：歩数は文章のリズム・描写密度・展開の速度を変えるが、物語の内容（ジャンル・筋）は変えない（指示どおり歩数に優劣をつけないため）。
   変化の手段は「描写文を入れるか」「長い文と短い文のどちらの版を使うか」「段落を何文で区切るか」「テンポに応じた追加場面（動きのある場面／内省の場面）を入れるか」の4つ。
4. **語の活用**：日本語は助詞・活用が変数の前後で崩れやすい。変数に入れる語は「名詞句」「完結した動詞句」など文法的な役割を固定し、全組み合わせを自動で描画して検査する。
5. **文学的な品質**：比喩の新鮮さ、余韻、感情の説得力は自動検査では測れない。人間評価シートを用意する。

## 文字数（1,000〜1,400字）について

- 場面ごとに「必須文」「描写文（削除可）」を分け、生成後に文字数を測って描写文を足し引きすることで範囲内に収める。
- テンポが速い日は描写文が減るぶん、追加の展開場面で文字数を補う。結果として「同じ長さでも、描写が多い物語」と「出来事が多い物語」になる。

## 試作データの規模

指示どおり、まず少量で検証します。

- ジャンル5（日常／恋愛／SF／ファンタジー／ホラー）× 骨格1
- 骨格あたり 7〜9場面、各場面1〜2変種、結末2〜3種
- 舞台 各骨格3か所、モチーフ 各骨格2〜3種、人物18名
- 共通の情景描写 約25文

この規模で品質検査（20編以上）を行い、問題点を確認してから骨格を増やす方針です。

# 検証結果（Ver.0.1 試作データ）

`npm test`（46項目）と `npm run report`（51編）の結果です。詳細は `reports/quality-report.md`。
開発中には別途 約900編を生成して、文字数と検査の警告がゼロになることを確認しました。

## 達成できたこと

- 51編すべてが 1,000〜1,400字、自動検査のエラー・警告ともに0件。
- 同じシードで 1,000歩 → 15,000歩 にすると、10組すべてで段落数が増え（約1.2〜1.5倍）、描写文の比率が下がった（平均 約0.16 → 約0.05）。平均文長も1組を除いて短くなった。
- 骨格・舞台・モチーフ・人称・性別の全組み合わせで全文が描画できることをデータ検査で確認（未定義の項目や代名詞の直書きはテストで止まる）。
- 分岐のすべての経路に、条件の合う結末が存在することを確認。
- 異なる骨格どうしの物語はほぼ重ならない（類似度 0.02 以下）。

## 確認された限界（隠さずに書きます）

1. **同じ骨格どうしの重なりが大きい**：類似度の中央値は約0.29、最大約0.69。
   1ジャンル1骨格の試作データでは、同じジャンルを数回読むと筋の共通性ははっきりわかる。
   単一の変種しかない場面に第2の変種を足したところ中央値が下がった（0.42 → 0.29）ので、
   **骨格と変種を増やすこと**が最も効く改善策。
2. **文字数は下限寄り**：平均約1,090字、テンポ「きびきび」では1,010〜1,100字が多い。
   描写文を足して長くするとテンポの差が消えるため、意図的に必須文（出来事）側を増やしている。
   約1,200字に寄せるには、各骨格に出来事の文をあと100字程度足す必要がある。
3. **話し方の性差**：日本語の会話文は性別・年齢で語尾が変わる。目立つ箇所は `{B^男性形|女性形}` で切り替えたが、
   ファンタジーの旅人の「無事か」「いいのか」のような口調は性別を問わずそのまま使っている（ジャンルの慣習として許容）。人間評価で確認してほしい。
4. **自動検査で見えないもの**：比喩の質、感情の流れ、季節感の細かな不一致（例：夏の夜に「冷たい」）などは、
   条件付きの文で防いでいるが網羅は保証できない。人間評価シート（`reports/human-eval.md`）で確認する。
5. **文の長さの差は小さい**：平均文長の差はテンポ間で1〜2字程度。テンポの違いは主に「段落の切り方」「描写文の量」「追加場面の種類」で生まれている。
   文そのもののリズムをもっと変えるには、主要な文に短い版（`fast`）・長い版（`slow`）を書き足す必要がある。
6. **文末の単調さ**：日本語の過去形は「〜た。」が続きやすい。5文連続を警告にしているが、4文以下の単調さは人間の判断に任せている。

## 次の段階の提案

- 各ジャンルに骨格を2〜3本追加し（1本あたり約4,000〜6,000字の執筆）、同ジャンルの類似度を下げる。
- 人間評価で点が低かった文・場面から直す（評価の集計は `reports/human-eval.csv`）。
- 骨格が増えた段階で、読者向けの画面デザインに進む。
