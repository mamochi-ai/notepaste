# note Paste Studio（プロトタイプ）

ChatGPTやClaudeが書いたMarkdown記事を、**見出し・太字・リスト・画像などの装飾を保ったまま**noteの編集画面に一括で貼り付けられるかを検証するためのWebツールです。

- iPadのSafariだけで使えます（PC不要）
- サーバー・外部API・APIキー・ユーザー登録は不要です
- 記事と画像はブラウザの中だけで処理し、外部サーバーへは送信しません
- GitHub Pagesにそのまま置ける静的サイトです（HTML / CSS / JavaScriptのみ、ビルド不要）

> **注意**：これは「できるかどうか」を確かめるためのプロトタイプです。noteの非公開APIは使わず、ログイン情報も扱いません。noteが貼り付けた内容をどう扱うかはnote側の仕様で決まるため、**このツールで「コピー成功」と表示されても、noteで装飾や画像が残ることは保証されません。** 実際の結果は検証画面で記録してください。

---

## 検証結果（iPadOS／Safari 26.5、2026年10月21日）

| 方式 | クリップボードへのコピー | noteへの貼り付け |
| --- | --- | --- |
| ① HTML＋data URL画像 | 成功 | 何も貼り付けられなかった |
| ② HTML＋Blob URL画像 | 成功 | 何も貼り付けられなかった |
| ③ HTML＋公開HTTPS画像URL | 成功 | 何も貼り付けられなかった |
| ④ HTMLのみ（画像は目印） | 成功 | **見出し・太字・箇条書き・番号付きリスト・引用・リンクが残った** |
| ⑤ 画像そのもの（image/png） | 成功 | **画像として貼れた** |
| ⑥ 旧方式 execCommand | 成功 | 何も貼り付けられなかった |
| ⑦ 手動選択コピー | — | 何も貼り付けられなかった |
| ⑧ 文章＋画像を同時に（1アイテム） | 成功 | 画像だけ貼れた（文章は消えた） |
| ⑨ 文章と画像を別アイテムで | 成功 | 文章だけ貼れた（画像は消えた） |

- 画像を含むHTMLは、画像の指定方法を問わずnoteに貼り付けできませんでした。noteは画像入りのHTMLの貼り付けを受け付けないと考えられます（note側の内部動作は確認できないため推測です）。
- 文章の装飾（見出し・太字・箇条書き・番号付きリスト・引用・リンク）は、画像を含めなければ1回のコピーでnoteに残りました。
- 画像は、画像データとして1枚ずつコピーすればnoteに貼れました。

- 文章と画像を同時にクリップボードへ入れても、noteはどちらか片方しか読み取りませんでした（⑧は画像を、⑨は最初の項目の文章を優先）。

**結論：今のnoteでは、画像まで含めて1回で貼り付ける方法は見つかりませんでした。** そのためエディタの既定の動作を **「文章を一括コピー → 画像を目印の位置に1枚ずつ貼る」** にしています。

## ファイル構成

```
index.html          エディタ画面（記事の入力・プレビュー・タイトル／本文／画像のコピー）

test.html           検証テスト画面（コピー方式ごとの検証・貼り付けテスト・結果記録）

js/markdown.js      Markdown→HTML変換（XSS対策込み・外部ライブラリなし）
js/article.js       コピー用HTML・プレーンテキスト・保存用HTMLの組み立て
js/clipboard.js     Clipboard API／旧方式コピー、環境チェック
js/images.js        画像の縮小・保存（IndexedDB）・PNG変換
js/common.js        共通UI・サンプル記事
js/editor.js        エディタ画面の処理
js/test.js          検証画面の処理
assets/             テスト画像・アイコン
tests/              Markdown変換のテスト（Node.js）
.nojekyll           GitHub PagesでJekyll処理を無効化
```

## iPadでの使い方

1. SafariでツールのURL（例：`https://<ユーザー名>.github.io/<リポジトリ名>/`）を開きます。
   共有ボタン →「ホーム画面に追加」で、アプリのように起動できます（Safariのデータ自動削除の対象にもなりにくくなります）。
2. ChatGPTやClaudeの回答をコピーし、「AIの回答を貼り付け」を押します（入力欄に直接貼り付けても構いません）。
3. 画像を入れたい位置で入力欄をタップし、「画像を追加」を押して「写真ライブラリ」または「ファイルを選択」から選びます。
   入力欄に `![名前](img:xxxxxxxx)` という指定が入ります。`img:` の後ろが画像の内部IDです。
4. 「noteに貼り付ける」の①〜③の順に進めます。
   - ① **タイトル**：「コピー」→ noteの記事タイトル欄に貼り付け
   - ② **本文**：「本文をコピー」→ noteの本文欄に貼り付け（見出し・太字・リスト・引用・リンクつき）
   - ③ **画像**：「画像1をコピー」→ 本文の「［画像1：…］」の位置に貼り付けて目印の文字を消す。コピーすると自動で次の画像に進みます
5. 次の記事を書くときは「新規」で記事と画像を消します。

スマートフォンや縦向きのiPadでは、画面下にコピー用のボタン（タイトル・本文・画像）が常に表示されます。

うまくいかないときは「うまくいかない場合」から、本文を選択して手動でコピー・装飾なしでコピー・HTMLファイルを保存できます。

### 設定

| 項目 | 内容 |
| --- | --- |
| 最初の「# 見出し」を記事タイトルとして分ける | noteはタイトル欄が本文と別なので、先頭の `# 見出し` を本文から外して①でコピーします |
| 見出しをnoteの大見出し・小見出しに合わせる | `#`・`##` → 大見出し（h2）、`###` → 小見出し（h3）、`####` 以下 → 太字の段落に変換します |

入力内容と設定はlocalStorageに、画像はIndexedDBに、この端末の中だけで自動保存されます。画像の埋め込み方式の比較などの検証機能は、ページ下部のリンクから開ける「検証ページ」にあります。

--- | --- |
| 画像の扱い | `画像は目印にして後から貼る`（既定・おすすめ）／検証用：`data URL`・`公開HTTPS URL`（テスト画像のみ）・`Blob URL`（いずれもiPad＋noteでは貼り付けできないことを確認済み） |
| 最初のH1を記事タイトルとして分ける | noteはタイトル欄が本文と別なので、先頭の `# 見出し` を本文から外して「タイトルだけコピー」で扱います |
| 見出しをnoteの大見出し・小見出しに合わせる | `#`・`##` → h2、`###` → h3、`####` 以下 → 太字の段落に変換します（noteの見出しが2段階であることを前提にした変換で、実際の取り込み結果は要検証です） |

入力内容・設定は端末内（localStorage）に、画像はIndexedDBに自動保存されます。

## GitHub Pagesの公開手順

iPadだけで公開できます。

1. GitHubにこのリポジトリのファイルを置きます（すでに置いてある場合は不要）。
2. ブラウザでリポジトリを開き、**Settings → Pages** を開きます。
3. **Build and deployment** の **Source** を「Deploy from a branch」にします。
4. **Branch** で公開したいブランチ（例：`main`）とフォルダ `/ (root)` を選び、**Save** を押します。
5. 1〜2分待つと、Pagesの画面上部に公開URL（`https://<ユーザー名>.github.io/<リポジトリ名>/`）が表示されます。

補足：

- Clipboard APIはHTTPSでのみ使えます。GitHub PagesはHTTPSで公開されるのでそのまま使えます。（Settings → Pages の「Enforce HTTPS」がオンになっているか確認してください）
- 非公開リポジトリでPagesを使うには有料プランが必要な場合があります。
- PCで動作確認する場合は、リポジトリのフォルダで `python3 -m http.server 8000` を実行し `http://localhost:8000/` を開きます（`file://` で直接開くとモジュールの読み込みやクリップボードが動きません）。

## テスト手順（iPad Safari）

検証画面（上部の「検証テスト」）を使います。

1. **この端末の対応状況** を確認します。「安全な接続（HTTPS）」「navigator.clipboard.write」「ClipboardItem」が「あり」になっているか見てください。
2. **サンプル記事**（「iPadだけでAI開発を始めてみた」）が表示されていることを確認します。
3. **コピー方式ごとの検証** で、方式を1つ選んで「コピー」を押します。
   - 「クリップボードへの書き込み：成功／失敗」と、失敗時のエラー名・内容が表示されます。
4. 同じページ下部の **このページでの貼り付けテスト** の枠を長押しして「ペースト」します。
   - クリップボードに入っていたデータの種類（text/html、text/plain、画像ファイルなど）と、貼り付け後に残った見出し・太字・画像の数、画像URLの種類が表示されます。
   - **ここでの成功は、noteでの成功を意味しません。**
5. noteの編集画面（別タブ）で本文欄に貼り付け、結果を確認します。
6. 検証画面に戻り、その方式のカードで「noteに貼り付けた結果」と「残った要素」を選び、メモを書いて「記録する」を押します。
7. すべての方式で繰り返します（①〜⑨はiPadOS／Safari 26.5で検証済み。別の端末やnoteの仕様変更後に再確認するときに使います）。記録は「テキストでコピー」「JSONを保存」で書き出せます。

### 検証する方式

| # | 方式 | 中身 | 見込み（未検証） |
| --- | --- | --- | --- |
| ① | HTML＋data URL画像 | `text/html` + `text/plain`。画像はHTML内に `data:image/...` として埋め込み | 外部通信なしで画像を運べる唯一のHTML方式。貼り付け先が data URL を除去する可能性あり |
| ② | HTML＋Blob URL画像 | 画像は `blob:` URL | Blob URLは発行したページ内でのみ有効なので、noteでは画像が出ない見込み（比較用） |
| ③ | HTML＋公開HTTPS画像URL | 画像はこのサイトに置いた `assets/test-image.png` の公開URL | noteが外部画像を読み込む・取り込む仕様なら表示される。自分で追加した画像には公開URLがないため使えない |
| ④ | HTMLのみ | 画像の位置に「［画像1：…］」の目印 | 文章の装飾だけを確認する用。画像は後からnoteで挿入 |
| ⑤ | 画像そのもの | `image/png` のバイナリのみ | HTMLに「画像の場所」を書くのではなく画像データ自体を入れる方式。画像1枚ずつ貼り付ける |
| ⑥ | 旧方式 execCommand | `document.execCommand('copy')` と copy イベントで `text/html` を設定 | Clipboard APIが使えない環境向けの代替 |
| ⑦ | 手動選択コピー | プレビュー本文を選択し、Safariのメニューで「コピー」 | Safariがコピー内容を作るため①〜⑥と結果が変わる可能性あり |
| ⑧ | 文章＋画像を同時に（1アイテム） | 画像なしの `text/html` + `text/plain` + `image/png` を1つの項目に | noteが両方を読むか、片方だけ読むかを確認 |
| ⑨ | 文章と画像を別アイテムで | 文章の項目と画像の項目を1回で2つ書き込む | 複数項目の書き込みに対応していないブラウザでは失敗（Chromeは非対応） |

## noteへの貼り付け確認項目

noteに貼り付けたら、次の項目を確認して記録してください。

- [ ] 貼り付け自体ができたか（何も起きない・エラーにならないか）
- [ ] タイトル：記事タイトル欄に正しく入ったか
- [ ] 大見出し（h2）が「大見出し」として認識されたか
- [ ] 小見出し（h3）が「小見出し」として認識されたか
- [ ] 太字が残ったか
- [ ] 箇条書き・番号付きリストが残ったか
- [ ] 引用が残ったか
- [ ] リンクが残り、タップで正しいURLが開くか
- [ ] 画像が表示されたか／画像の位置は正しいか
- [ ] 画像がnote上で通常の画像として扱われているか（下書き保存→再読み込みしても消えないか、公開プレビューで表示されるか）
- [ ] 画像の後に続く文章が正しい位置にあるか
- [ ] 余計な空行や不要な文字（目印・記号）が入っていないか
- [ ] 下書き保存してから再度開いても装飾が残っているか

特に画像は、**貼り付け直後に表示されても、保存時にnoteのサーバーへ取り込まれず消える**可能性があります。必ず下書き保存→再読み込みで確認してください。

## 既知の制限事項

- **画像を含むHTMLは、iPad Safari＋noteで貼り付けできないことを確認しました**（上の検証結果）。そのため画像は1枚ずつ貼る必要があります。
- **iPad Safari以外の環境でのnoteの結果は未検証です。** このツールはnoteの画面を操作・判定できません。noteは貼り付けられたHTMLを独自に整形・削除するため、装飾や画像が残るかは実際に試す必要があります。
- **画像**
  - Blob URLは他のサイト（note）では読み込めません。比較用です。
  - data URLは、貼り付け先・ブラウザが安全上の理由で除去する場合があります。また画像が多いとHTMLが大きくなります（3MB超で警告を表示）。
  - 公開HTTPS URL方式は、このツールに画像をアップロードするサーバーがないため、同梱のテスト画像でのみ使えます。
  - 画像バイナリ（image/png）はHTMLとは別にコピーします。1回のコピーで「文章＋複数の画像データ」を入れる方法はありません。
  - 長辺1600pxを超える画像は縮小し、JPEGは再圧縮します。HEIC画像はSafariが変換できる場合のみ扱えます。
- **Safariの制約**
  - クリップボードへの書き込みは、ボタンを直接タップした処理の中でしか許可されません。このツールはタップ直後に書き込むよう実装していますが、Clipboard APIが失敗した後の旧方式による再試行は、許可が切れていて失敗することがあります。その場合は「記事全体を選択」で手動コピーしてください。
  - `ClipboardItem.supports()` がないSafariでは、対応形式を事前に判定できません（「判定できません」と表示します）。
  - Safariは一定期間（7日程度）サイトを使わないと、サイトが保存したデータ（下書き・画像・記録）を削除することがあります。大事な記録は書き出してください。
- **Markdown**：見出し、太字、斜体、取り消し線、箇条書き（入れ子）、番号付きリスト、チェックリスト、引用、リンク、画像、区切り線、コード、表に対応しています。HTMLタグは安全のためすべて文字として表示します（`<br>` のみ改行として扱います）。noteが対応していない装飾（斜体・表・コードなど）は、noteへの貼り付け時に変換・除去される可能性があります。
- 段落内の改行は改行（`<br>`）として扱います。

## セキュリティ

- Markdownの変換では入力中のHTMLをすべてエスケープし、許可したタグ（見出し・段落・強調・リスト・引用・リンク・画像など）だけを生成します。
- リンクは `http` / `https` / `mailto` のみ、画像は `img:ID` / `https` / `data:image/(png|jpeg|gif|webp)` のみ許可します。`javascript:` などは無効化します。
- Content-Security-Policy でスクリプトを同一オリジンのファイルのみに制限しています。
- 検証用の貼り付け領域では、貼り付け後にスクリプト・iframe・イベント属性などを除去します。クリップボード内容の解析は、スクリプトも画像読み込みも実行しない DOMParser で行います。
- 外部への通信は、記事中に `https://` の画像URLを書いた場合にその画像をプレビュー表示するときだけです。

## 開発

ビルドは不要です。Markdown変換のテストは Node.js 18 以降で実行できます。

```sh
npm test          # node --test tests/*.test.mjs
npm run serve     # http://localhost:8000/ で確認
npm run bump      # 公開前に実行（CSS・JSの読み込みURLのバージョンを更新）
```

GitHub PagesはCSSやJSを約10分キャッシュさせます。HTMLだけ新しくなって表示が崩れないよう、変更を公開する前に `npm run bump` を実行してください。
